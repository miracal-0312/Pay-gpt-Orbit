# 开发与验证

所有命令均从仓库根目录执行。生产启动方式见[部署](../operations/DEPLOY.md)。

并发保护包括事务行锁、订单执行锁、卡分配锁及共享等待位锁。MySQL 行锁保证 CDK、订单、卡片计次原子结算；命名执行锁协调受理、后台支付和恢复查询，自助按 CDK 锁定，管理员按请求编号锁定，人工交付同时锁定 CDK。固定命名锁保证用户与管理员全局只有一个等待任务；等待任务保留在执行集合中，避免恢复流程误收尾，对外运行中数量单独扣除等待任务。卡分配锁与最终预占事务保证同卡不并行占用。重复请求只读原单或返回处理中；恢复取锁后重读状态，不用旧快照释放其他执行者的订单。

管理员[显式解除本地占用](../operations/ORDER-MANUAL-CONTROL.md)是默认保留未决占用规则的例外，仍需二级验证、执行锁、最新版本及实际归属校验，并在同一事务中追加审计。已释放旧单使用独立的原单核对锁继续处理原资金，迟到结果不得修改新订单的 CDK 或卡片占用，也不得恢复旧单支付；原平台状态、请求正文与幂等身份保持原义，本地释放不代表退款。

执行锁和选卡锁使用独立 MySQL 连接，不占用 `DB_POOL_LIMIT` 控制的业务查询连接池。进程退出或连接断开时 MySQL 释放锁；当前执行者在写入资金操作前检查执行权。已经写入的开卡、补款、订阅身份继续保留，由原单恢复流程核对。数据库死锁或锁等待超时仅在确认回滚后重试，最多 3 次；提交结果不明、业务错误和回滚失败不重试，事务内不得调用平台支付接口。

失败或拒绝的旧订单不会被迟到的成功结果重新打开，已绑定的平台订单号不可被另一订单号覆盖；准备阶段的订单不能直接按订阅查询结果结算。这些并发保护不依赖 Redis；商城核销通知所需的配置与通知表见[商城核销通知](../integrations/CDK-REDEMPTION.md)。部署及连接数限制见 [DEPLOY.md](../operations/DEPLOY.md)。

可先用 Python 3.10+ 标准库脚本检查真实 Orbitcard **读取权限与响应字段**。在执行脚本的环境中设置 `ORBITCARD_API_KEY` 和 `ORBITCARD_API_SECRET`，再复制 [配置示例](../../scripts/orbitcard-openapi-check.example.json) 到仓库外的路径；JSON 只保存非敏感检查参数。`card_id` 留空时自动选列表中的首张卡；有原订单时可填写 `task_no` 或 `client_order_no` 其中一个。运行：

```bash
python -X utf8 scripts/check_orbitcard_openapi.py --config /path/to/private-orbitcard-check.json
```

若只需按 `getProductCode` 核实产品、库存和最低金额字段，可加 `--products-only`；此模式只发送一次签名的只读产品查询，不调用其他接口。

脚本检查账户余额、开卡产品、订阅套餐与目录、各已启用套餐的支付地区、分页卡列表、批量与单卡详情、脱敏交易与卡流水、订阅列表，以及配置了编号时的原订阅详情。`getProductCode` 在此脚本中仅用于核实开卡产品、库存、最低首充和留存字段，不构成现有卡充值或只读选卡预检的门槛；套餐 USD 卡支付金额由本项目后台配置，不能从订阅服务费或历史订单金额推测。`max_cards` 默认 20、最多 1000；仅输出字段白名单摘要，不输出 API 凭据、完整卡号、CVV、Session 或原始响应。脚本只允许读取接口，不会开卡、补款或提交订阅。退出码 0 表示已执行的检查成功，2 表示有接口或字段失败，3 表示配置错误；没有卡或未填订单编号时对应检查会标为 `skipped`。真实平台读取仍需要相应 Scope 和允许的服务器出口 IP。

```bash
npm run check
npm test
python -m unittest discover -s test -p 'test_*.py'
```

`npm run check` 检查 JavaScript 语法、相对模块路径和大小写、文档本地链接及关键部署路径。Python 测试仅验证只读检查脚本，不读取生产凭据或请求真实平台。

测试包括 HMAC 签名、CDK 与卡片预占事务、订阅提交原子认领、确认卡片相关失败后最多两次换卡、已用卡排除、额度持久化及 Session 恢复、无卡或耗尽售后锁定，以及卡片错误停用、唯一补开与人工状态恢复。也覆盖并发预占、USD 金额及地区校验、批量选卡、套餐整额补款与原资金意图恢复、未知订阅只查原单、服务费隔离、API 限流、日志脱敏及管理员权限。使用模拟数据库和上游，不发起真实开卡或充值。

支付核心集成测试串联业务模块与模拟上游、事务数据库，验证四档套餐核销、套餐整额补款、确认缺卡时开卡、历史对账异常时选用合格卡、卡片错误换卡重试、补款超时工单与重启只读对账、订阅未知保留原单，以及数据库故障时保留未知资金占用。

人工处理专项覆盖未决资金下独立登记人工结果、明确选择本地释放与默认不释放、严格布尔参数、首次释放记录保留、错误归属拒绝、事务回滚，以及释放后迟到回执不影响新订单。界面测试验证原资金状态、人工结果和本地释放标记分别展示，备注／暂停不能携带释放选项。

并发回归测试包含 30 个同 CDK 抢占、两个独立服务实例共享订单、异步提交期间的重复请求、恢复读取旧快照、锁连接丢失、迟到终态、补款意图与释放竞争，以及死锁重试边界。此测试使用模拟 MySQL 锁连接与事务，不替代服务器上的真实 MySQL 多连接压测。

容器体积需在实际构建后测量；不再下载安装 Chromium、PyTorch 等组件。更换轻量镜像不会自动删除服务器上的旧镜像或构建缓存。
