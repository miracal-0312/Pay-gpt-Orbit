# 调试与日志

「调试与日志」集中提供五个子页：「接口查询」用于一键检查 14 项已接入接口，并提供独立的 Telegram 通知测试；「支付预检与测试」用于只读预检、并发模拟和真实扣款测试；「订单链路」用于管理员订单记录及按编号查看、下载链路日志；「运行日志」用于运行事件；「登录记录」用于登录审计。真实扣款测试只有「支付预检与测试」一个入口，「手动开通」保留人工交付，订单行保留日志快捷入口。旧 `#logs` 地址会进入「运行日志」。

「接口查询」点击「一键全部测试」，依次检查项目当前注册的 14 项接口：10 项只读操作发送真实平台请求，其中地区查询覆盖四档套餐；开卡、补款、删卡和订阅这 4 项财务写操作仅在本地模拟请求参数与幂等键校验，不发送平台。单项失败仍继续后续项目，分别显示模式、状态、耗时和摘要，并汇总结果；运行中不能重复发起。全部测试使用已保存的平台配置，修改根域名等参数后需先保存。

依赖卡片或原订单的读取会自动选择现有卡、已有原订单；缺少必要依赖时显示“跳过”，不计为通过。本地写模拟通过只表示参数与幂等键校验通过，不能证明平台真实开卡、补款、删卡或支付权限有效，也不代表真实扣款成功。范围仅含本项目已接入的 14 项，不包含冻结、退款等未接入操作，也不包含 Telegram 发送或真实支付；Telegram 测试仍为独立按钮。

完成二级验证后，在「支付预检与测试」读取可选套餐，选择 Plus 或三档 Pro，地区沿用已保存的默认地区。上传或粘贴 Session 可分步或完整预检，展示现有卡的选卡、补款、等待或不可支付原因；不预占卡、不改卡片记录、不创建订单或执行资金操作，缺卡停止。预检通过只代表当前快照通过，正式支付会重新验证，实际费用以平台为准。

平台没有独立的 Session 上传接口。本地预检只验证 JSON、必要字段和过期时间；「真实扣款测试开通」才随 createSubscription 将 Session 发往卡台，需确认账号授权及真实扣款，复用管理员 test 订单，不消耗 CDK。测试编号在当前标签页保留，提交超时查询原编号，未知结果不能换编号重付。明确卡片相关订阅失败才在同一测试请求内换卡，最多追加两次尝试；Session 不可用时用原测试编号及同账号新 Session 继续剩余额度。原测试最终结束后才能开始下一笔。Session 不写浏览器存储或日志，受理后清空页面中的 Session。

「并发选卡模拟」无需 Session，支持 2–100 个同套餐任务同时到达选卡阶段。读取本地停用记录和一轮实时卡片快照，在内存复用正式选卡规则，按分配锁串行重选，共享模拟占用和补款预算。逐任务展示首选、最终分配、补款金额及等待原因，统计模型内重复分配；数据库和资金不变。本轮模拟占用不释放，现有卡暂被占用时最多 **1 个任务等待**，后续需等待的任务标为 `blocked`，原因为 `queue_full`，提示 10 分钟后下单；无合格卡时停止，不模拟新开卡。不套用线上执行名额上限，也不模拟支付完成、真实数据库锁竞争、锁超时、网络故障或多实例行为，不能替代真实 MySQL 压测。“完成模拟”只表示模拟执行完毕，不代表所有任务可支付。

「订单链路」集中管理员订单列表，显示第 N / 3 次和历史用卡日志，以及 Session 本地校验、套餐、地区、选卡与排除原因、补款、换卡尝试、提交和原单查询日志。预检使用 debug-… 编号，真实测试使用 manual-… 编号；订单列表的「链路日志」快捷入口打开同一查看器。每 10 秒读取后续记录，每页最多 200 条，页面保留容量内最近 1000 条，保留期内完整日志可下载。运行日志和订单日志按北京时间日期保存，保留当天及之前 14 天；清空显示缓存不影响磁盘文件。可查看 API 路径、HTTP 状态、平台代码、耗时和安全参数摘要，不记录 Session 内容、访问凭据、完整卡号或 CVV。文件位置及迁移见 [部署说明](DEPLOY.md#环境更新与存储)。

自动化回归与独立只读检查脚本见[开发验证](../development/TESTING.md)。卡片错误和平台错误的处理措施见[故障处置](ORBITCARD-CARDS.md#故障代码与处理措施)。
