# 管理员邮件通知

邮件用于提醒管理员处理订单与平台资金，独立于充值链路。SMTP 配置、发送失败和重试不会改变订阅结果、释放支付占用或再次发起开卡、补款、订阅。

## 配置与启用

1. 在后台打开「接单与安全」，完成二级验证，找到邮件通知设置。
2. 填写邮箱服务商提供的 SMTP 主机、端口、用户名与密码或授权码。填写发件邮箱和管理员收件邮箱；目前使用一个收件地址。
3. 默认使用端口 `465` 的直接 TLS；如服务商使用 `587`，选择 STARTTLS。STARTTLS 模式要求服务器支持加密，不降级为明文连接。
4. 保存配置后，点击「发送测试邮件」，检查管理员邮箱。测试使用已保存配置和固定测试正文，不携带真实订单。
5. 选择余额预警、充值成功、充值失败的通知开关，再启用邮件通知。

默认关闭邮件通知；余额预警阈值为 `50.00 USD`，持续低余额提醒间隔为 `360` 分钟，均可在后台修改。阈值指卡台账户的 `available_balance`，不是某张支付卡余额，也不是客户需要另付的费用。

SMTP 密码加密存储在数据库中，网页不会回显密码。编辑时留空保留原密码，清除使用独立选项。加密依赖服务器的 `ADMIN_TOKEN_SECRET`，备份数据库时也须保管原服务器配置；变更该密钥后需要重新保存 SMTP 密码。密码、授权码和原始 SMTP 错误不会写入通知记录。

## 通知内容与触发条件

| 类型 | 条件与内容 |
| --- | --- |
| 账户余额预警 | 成功读取且账户可用余额低于阈值时提醒。包含可用余额、阈值和检查时间。查询失败、权限异常或字段缺失不当成余额为零。 |
| 充值成功 | 数据库订单具有来源与归属一致的订阅成功证据。包含来源、订单/任务标识、套餐、目标账号及结果时间。人工核销不等同于卡台订阅成功。 |
| 充值失败或未完成 | 记录最终失败或需要人工处理的未完成订单。已验证失败与未提交/未确认分别表述；正在换卡重试、处理中或等待验证的订单不作为最终失败发送。 |

自助兑换、管理员测试和人工交付均纳入通知，邮件区分来源。金额仅在能够从已验证结果中确定时展示，不把后台配置价格当作实际扣款。邮件不包含完整 CDK、Session、签名、完整卡号或 CVV。

新启用时以启用时间为界发现后续更新的订单，不批量发送之前已结束且未再变化的历史订单。数据库时间为秒精度，启用所在秒的订单更新可能被纳入。

## 去重、恢复与发送记录

后台每 30 秒处理一次通知；余额读取最多每 5 分钟一次，平台限流时按等待时间延后。持续低余额按配置间隔提醒，余额恢复后再次跌破会重新预警。预警状态按平台和 API 身份隔离，并持久化保存。

订单事件按业务链和结果去重。通知先写入独立队列，再进行 SMTP 发送，重启后继续处理待发送记录；失败按退避间隔有限重试。更改收件地址不会把旧队列中的订单信息转发给新收件人。关闭总开关或某一通知类型后，不再开始相应自动发送。

后台显示近期通知的事件、状态、尝试次数与安全错误码。SMTP 服务已经接收邮件而应用来不及确认时，恢复重试仍可能重复；因此邮件提供固定事件标识，订单事实以后台及卡台原订单为准。

## 更新与排查

更新代码后执行依赖安装或重建应用镜像，安装新增的 `nodemailer` 依赖。启动时自动建立邮件队列、订单观测及余额预警的独立表；数据库账号需要建表权限。其余部署步骤见[部署与升级](DEPLOY.md)。

- 配置不完整：核对主机、端口、TLS 模式、账号、发件和收件邮箱。
- 身份验证失败：确认使用服务商要求的 SMTP 授权码，账号已开放 SMTP。
- 连接或 TLS 失败：检查服务器出站网络及邮箱服务商端口要求，保留证书校验。
- 密码无法读取：服务器加密密钥可能已变更，重新保存 SMTP 密码。
- 没有订单邮件：核对总开关、对应事件开关和订单是否已满足终态条件；人工核销及仍待确认的结果不视作已充值成功。
- 余额没有更新：核对卡台账户读取权限、凭据和限流状态，邮件队列不会代替资金对账。

SMTP 选项依据 [Nodemailer SMTP 文档](https://nodemailer.com/smtp)和[邮件参数文档](https://nodemailer.com/message)。本项目强制加密传输与证书验证，不支持附件、HTML、文件或 URL 内容读取。
